# Пирамида тестирования

> **NovaTech / FirstDay AI — учебная демонстрационная документация.** Компания, системы, процедуры и сроки вымышлены и не являются правилами реального работодателя.

## Назначение и контекст

Unit tests проверяют небольшие функции, integration tests — взаимодействие с БД и сервисами, E2E tests — полный пользовательский сценарий. E2E медленнее и не заменяет unit tests.

## Для кого эта инструкция

**Аудитория:** ENGINEERING,QA. **Владелец:** Quality Engineering. **Уровень доступа:** EMPLOYEE. **Статус:** Published.

## Порядок действий

1. Для новой логики добавьте unit tests.
2. Для persistence добавьте integration tests.
3. Для критического пути добавьте E2E.
4. Проверяйте отрицательные сценарии.
5. Запускайте тесты в CI.

## Типичные ошибки и способы решения

- **Ситуация 1.** Flaky-тест должен быть исследован, а не просто отключён.
- **Ситуация 2.** Тестовые данные не должны содержать реальных персональных данных.

## Вопросы и ответы

**Вопрос:** Что тестируют integration tests?

**Ответ:** Взаимодействие компонентов, например API и БД.

**Вопрос:** Заменяют ли E2E unit tests?

**Ответ:** Нет.

## Контрольный результат

После выполнения инструкции сотрудник должен уметь объяснить, зачем нужен описанный процесс, показать выполненные действия или заявку в учебной системе Nimbus, а при блокере — указать ответственного владельца. Если шаг невыполним, его следует отметить как заблокированный, а не как завершённый.

## Как поддерживать актуальность

Уточнения и исправления передаются через заявку **Knowledge Feedback** в Nimbus, обязательно с названием документа **NT-035**, описанием противоречия и предложением исправления. Сотрудник не должен менять утверждённые политики только на основании ответа AI.
