# Runbook: pgAdmin Restarting / empty response

> **NovaTech / FirstDay AI — учебная демонстрационная документация.** Компания, системы, процедуры и сроки вымышлены и не являются правилами реального работодателя.

## Назначение и контекст

pgAdmin контейнер может перезапускаться, если PGADMIN_DEFAULT_EMAIL не проходит проверку. Демонстрационная проблема: admin@firstday.local отклонён из-за специального домена .local. Решение — корректный адрес и пересоздание только pgAdmin.

## Для кого эта инструкция

**Аудитория:** ENGINEERING,DEVOPS. **Владелец:** Developer Enablement. **Уровень доступа:** EMPLOYEE. **Статус:** Published.

## Порядок действий

1. Проверьте docker ps -a.
2. Посмотрите docker logs для pgAdmin.
3. Исправьте переменную PGADMIN_DEFAULT_EMAIL.
4. Пересоздайте pgAdmin, не PostgreSQL.
5. Проверьте UI и порт 779.

## Типичные ошибки и способы решения

- **Ситуация 1.** Не удаляйте том PostgreSQL для исправления pgAdmin.
- **Ситуация 2.** Ошибка ERR_EMPTY_RESPONSE сама по себе не доказывает проблему БД.

## Вопросы и ответы

**Вопрос:** Почему pgAdmin постоянно перезапускается?

**Ответ:** Одна из причин — невалидный PGADMIN_DEFAULT_EMAIL.

**Вопрос:** Нужно ли удалять PostgreSQL?

**Ответ:** Нет.
